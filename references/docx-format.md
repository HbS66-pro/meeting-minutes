# docx 格式与脚本约定

## 一、格式规范

| 元素 | 字体 | 字号 | 其他 |
|---|---|---|---|
| 主标题 | 黑体 | 三号 16pt | 加粗、居中 |
| 一级标题（一、二、三） | 黑体 | 三号 16pt | 加粗 |
| 二级标题（1. 2. 3.） | 黑体 | 四号 14pt | 加粗 |
| 正文 | 宋体 / 西文数字 Times New Roman | 小四 12pt | 首行缩进 2 字符 |
| 行距 | — | — | 固定值 28 磅，段前段后 0 |
| 重点 `**…**` | 同正文 | 同正文 | 加粗，黑色 |
| 更重点 `==…==` | 同正文 | 同正文 | 加粗，蓝色 #0000FF |

要改格式改 `scripts/md2docx.py` 顶部的 `SPEC` / `LINE_SPACING_PT` / `FIRST_LINE_CHARS` 常量，别在 Word 里手调——手调的内容下次重新生成就没了。

## 二、脚本认的 Markdown

只认这一小套，比通用 Markdown 解析可控：

| 写法 | 变成 |
|---|---|
| `# 会议主题（日期）` | 主标题，居中（只有第一个 `#` 是主标题） |
| `## 一、会议概要` | 一级标题 |
| `### 1. 主题` | 二级标题（`###` 及更深的 `#` 都按二级） |
| `---` | 忽略，不进文档 |
| 其余非空行 | 正文段（空行分段，一行一段） |
| `- 事项` | 正文段（去掉 `- `） |
| `> 引文` | 正文段（去掉 `> `） |
| 行内 `**加粗**` | 加粗黑色 |
| 行内 `==加粗蓝==` | 加粗蓝色，可写 `**==两者叠加==**` |

**兼容旧稿**：整行只有 `**…**` 时也当标题——第一个无序号的行按主标题（已有主标题时按一级）；含"一、二、"等中文序数按一级；含"1.""2."按二级。所以旧的纪要 md 不用改就能重新出 docx。

**注意**：正文里不要用孤立的 `**` 或 `==`（比如写"参数 == 阈值"），会被当成强调标记；脚本遇到落单标记会在 stderr 报警并保留原文。

## 三、用法

```bash
python scripts/md2docx.py 草稿.md              # 输出同名 .docx
python scripts/md2docx.py 草稿.md 成稿.docx    # 指定输出
python scripts/md2docx.py 草稿.md --check      # 生成后立刻校验格式
```

`--check` 会重新打开产物逐段核对：段落数、文字、对齐、行距是否固定 28 磅、段前段后是否为 0、首行缩进是否 2 字符、每段中西文字体字号、蓝色强调是否为 #0000FF 且加粗。全部通过打印 `格式自检通过：N 段`，否则逐条列出问题并以退出码 1 结束。

依赖只有 `python-docx >= 1.0`，不需要 pandoc、不需要 LibreOffice。宋体、黑体是 Windows 中文版自带字体；在 macOS 或没装中文字体的机器上打开会被替换，交付前在目标机器上看一眼。

## 四、出稿后的两件事

- **打开看一眼**：中文是否正常、蓝色强调是否只在关键处、加粗是否均匀。格式自检管不了"好不好看"。
- **不要手改 docx 再存**：改了要回头改 md 重新生成，否则下次生成覆盖掉手改内容。

## 五、命名

`{日期}_{主题}_纪要.docx`，外部专家指导的会议在主题里写明，如 `3.12_公园改造方案二稿（陈老师指导）_纪要.docx`。存放位置由用户指定，没指定就放当前目录。
