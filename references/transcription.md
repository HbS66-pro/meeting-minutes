# 转写：从音频到文字

> 本 skill 从**文本**开始，不做语音识别。这份文件只解决"文本从哪来"。
> 现状：转写这一步还没全自动，四条路各有代价，按场景选一条，别每次都重新调研。

## 一、先看手里有没有现成文本

按顺序排除，能省一步是一步：

1. 平台/会议软件自带字幕（B 站、腾讯会议回放、课程平台）→ 直接下字幕，别转写。
2. 会后已有转录（讯飞、飞书妙记、夸克、手机自带）→ 直接用，先核对说话人。
3. 只有音频 → 走下面四条路。

## 二、四条路

### A 云端一键转写（1–3 小时中文会议，首选）

**夸克「录音纪要」**（手机 App / 网页端的「万能转换中心」，桌面端入口随版本变动）：

- 可实时录，也可上传本地音频或**已在夸克网盘里的录音**——这就是"上传网盘再转"那条思路的落地形态，不需要桌面自动化。
- 能力：中文等 10 种语言自动识别，**支持多人对话、区分说话人**，产出完整转写 + 摘要/结论/待办，可查看、编辑、导出。
- 限制：免费转写有时长/额度上限（政策常变，用前看页面提示）；**必须上传**，涉密会议别走这条。

同类备选：通义听悟、飞书妙记、讯飞听见、腾讯云 ASR。中文标点与热词通常比本地小模型好，代价同样是上传。

**为什么优先**：多人会议最难的是"谁说的"，云端基本自带说话人分离，本地 Whisper 家族默认没有。

### B 本地 Whisper 家族（离线、批量、隐私敏感）

| 形态 | 是什么 | 适合 |
|---|---|---|
| `faster-whisper` | 基于 CTranslate2 的 Whisper 实现，不用 PyTorch，约 100 MB | **主链**：CPU 上最快，装完即用 |
| `openai-whisper` | 官方 Python 包，带 PyTorch，几个 GB | 已有 PyTorch 环境时顺手 |
| `whisper.cpp` | C/C++ 版 + 量化模型 | 老机器、要嵌到别的程序 |
| **Buzz** | GitHub 桌面版（chidiwilliams/buzz），底层 Whisper | 不想敲命令，拖文件选模型导出 txt/srt |

选型：

- 模型体积：base 141 MB / small 464 MB / medium 1.46 GB / large-v3 2.95 GB。
- **16 GB 内存的机器别碰 large-v3**：模型加运行内存要吃掉好几个 GB，CPU 上实测约 3 倍音频时长。
- 中文会议从 `small` 起步，术语错得多再上 `medium`；先拿 10 分钟片段试跑，再跑整场。
- 另有 VoiceStudio 这类整套语音套件（GitHub，安装约 10 GB，转写底层也是 faster-whisper）：为了转写不值得装，它的卖点是克隆与配音，且吃 NVIDIA 显卡。

faster-whisper 最小用法：

```python
from faster_whisper import WhisperModel

model = WhisperModel("small", device="cpu", compute_type="int8", cpu_threads=6)
segments, info = model.transcribe("会议.m4a", language="zh", vad_filter=True, beam_size=5)
with open("会议.txt", "w", encoding="utf-8") as f:
    for s in segments:
        f.write(f"[{int(s.start // 60):02d}:{int(s.start % 60):02d}] {s.text.strip()}\n")
```

**局限**：默认不做说话人分离。要人名，要么走云端，要么会后手工标"说话人 1/2/3"，要么另装 WhisperX/pyannote（本地加这一层要额外折腾）。归纳模式可以先不标，叙事模式必须标。

### C 手机转写 → 存 md（零环境，最省事）

手机录音机/语音备忘录（较新系统自带转写）、讯飞语记、飞书妙记 App 都能录音即转写：

1. 会上用手机录，或会后把音频传手机；
2. 用自带/App 的转写功能出文字；
3. 复制或导出，存成 `{日期}_{会议}_转录.md`，跟会议材料放一起；
4. 交给 agent 时说一句"转录在 xxx.md，按归纳模式出纪要"。

适合临时会议、没有电脑在手、内容不宜上传第三方云盘（手机本地转写）。缺点是分段和说话人标注通常很粗，需要人工过一遍。

### D Windows-MCP 驱动 GUI（最后手段）

有些工具只有界面没有导出（剪映的自动字幕、某些会议软件的回放、没有网页入口的桌面客户端）：

```text
客户端打开音频 → 触发自带"自动字幕/转写" → 导出 → 落到会议目录
```

用桌面自动化（截图 + 点击）去驱动。**只在**一次性任务、界面稳定、有人盯着时用；界面一改就断，不适合批量和无人值守。

## 三、怎么选

| 情况 | 走哪条 | 备注 |
|---|---|---|
| 1–3 小时中文会议，可上传 | A 夸克/通义 | 自带说话人分离，最省事 |
| 涉密、未公开数据、他人隐私 | B 本地 faster-whisper | 不上传 |
| 要叙事模式（必须有人名） | A 云端 | 本地无说话人分离 |
| 批量、反复跑 | B 本地 | 脚本化，可排队 |
| 只有手机 | C 手机转写存 md | 零环境 |
| 平台已有字幕 | 直接下字幕 | 最省力 |
| 只有 GUI 工具 | D Windows-MCP | 一次性 |

## 四、交接格式（本 skill 的输入约定）

不管走哪条路，转写稿整理成下面这样再交给纪要环节：

1. **UTF-8 纯文本，一行一段，空行分段**——生成脚本按行取段。
2. **说话人标注**：`说话人1：……`，开头先列身份对照（谁是谁）；不确定写"参会者"。归纳模式可以不要，叙事模式必须有。
3. **时间戳可选**：`[00:12:34]` 开头，方便回查原话；不要时间码也能写纪要。
4. **术语先行**：会前把项目名、专业词、人名列成一列，转写完统一替换。同音错字是转写稿最常见的坑，人名、项目代号、专业术语最容易错（比如"品位/品味"）。
5. **不改口语**：转写稿保留原话，删改留到写纪要时做——先改一遍反而丢证据。

## 五、质量与隐私

- **隐私**：上传前判断内容性质；云端服务的免费额度、留存期各家不同。
- **术语**：转写错字不影响归纳模式出结论，但会影响数字、金额、人名——这三类必须回听或对照材料核。
- **转写稿是敏感文件**：含真实姓名和未公开内容，别提交到仓库或公开分享。
- **长会分段**：超过 1 小时的音频先切段跑，中途失败不丢已转内容。
