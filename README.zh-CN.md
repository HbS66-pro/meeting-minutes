# meeting-minutes

把 1–3 小时的会议转录整理成正式会议纪要的 Agent Skill，中英文会议都支持，附带一个独立的 Markdown 转 Word 排版脚本。

English: [README.md](README.md)

这个 skill 最初是我在备战**中国国际大学生创新大赛**时攒出来的，那阵子几乎天天开逐页打磨会、专家指导会和赶截止前的修改会，靠人工听录音理清单太费时间。后来拿去跑实验室组会、项目评审和客户沟通，套路同样顺手，就整理成了通用技能。

项目按标准 `SKILL.md` 约定编写，支持 Agent Skills 的工具都能直接加载；里面的 `scripts/md2docx.py` 也可以单独拿来把 Markdown 转成排版规范的 `.docx`。

## 三种输出模式

同一份会议转录，根据给谁看，可以按三种详细程度输出：

| 模式 | 适用场景 | 保留内容 | 常见篇幅 |
|---|---|---|---|
| 叙事 `narrative` | 内部存档、组内交接、事后复盘 | 谁提了什么、谁追问、最后怎么定下来的 | 原转录的 10–20% |
| 归纳 `inductive`（默认） | 送审、评审反馈、修改清单 | 问题、结论和改法，去掉人名 | 原转录的 8–15% |
| 总结 `brief` | 群内转发、个人待办 | 编号结论和待办事项，不留过程 | ≤400 字，5–15 条 |

### 效果对比

以 [`examples/demo.md`](examples/demo.md) 里的一小段虚构转录为例：

```text
说话人1：先过采购清单，超净台两台，预算 12 万。
说话人2：12 万含安装吗？
说话人1：不含，安装另算，大概 8 千。
说话人3：那不如买一台大的，两台小的占地方。
说话人1：大的交期 10 周，赶不上 11 月验收。
说话人2：交期优先，两台小的就两台小的，安装费写进预算。
说话人3：行，房间我来腾。
```

**归纳模式**会隐去人名，按议题整理成「现状、结论、做法」：

> **1. 预算必须写明含安装**
> 现清单 12 万不含安装，安装另需约 8 千，预算存在缺口。清单按「含安装」重报，安装费单列，避免执行时再补。
>
> **2. 维持两台小超净台**
> 改买一台大台可省空间，但交期 10 周，赶不上 11 月验收。**按交期优先，仍采购两台小台**，房间由使用方腾空。

**总结模式**直接压成重点和待办：

> **重点**
> 1. 采购预算改为含安装，总额约 12.8 万。
> 2. 仍买两台小超净台，大台交期赶不上 11 月验收。
>
> **待办**
> 1. 重报采购清单——采购（11.5）
> 2. 腾空房间——使用方（本周）

包含叙事模式在内的完整三版对比见 [`examples/demo.md`](examples/demo.md)。

## 先读项目材料再动笔

开始整理前，skill 会先去工作区里找和这次会议相关的材料，比如上一次纪要、PPT、申报书、术语表或进度记录。摸清项目背景和上次定过的事，写出来的纪要才不容易把专业叫法写歪，也能接上上下文；如果工作区里找不到，它会先问目录在哪，不会硬猜。

输出语言跟着会议本身走：中文转录出中文纪要，英文转录出英文纪要。

## 安装

克隆后复制到你的 agent 技能目录即可（比如 `~/.claude/skills/` 或 `~/.dsh/skills/`）：

```bash
git clone https://github.com/HbS66-pro/meeting-minutes.git
cp -r meeting-minutes ~/.dsh/skills/meeting-minutes
```

## 用法

在对话里直接吩咐：

> 转录在 `会议转录.md`，按归纳模式出纪要，存到当前目录。

平时说自然语言就行：提「要留过程 / 谁说了什么」走叙事模式；说「只要重点 / 列个待办」走总结模式；不特别指定时默认走归纳模式。

英文会议同理：

> Transcript is in `meeting.md`. Inductive minutes, please.

### 单独生成排版 docx

如果只想要 Word 排版脚本，不走 agent：

```bash
python -m pip install "python-docx>=1.0"
python scripts/md2docx.py 草稿.md 成稿.docx --check            # 中文排版
python scripts/md2docx.py notes.md out.docx --lang en --check  # 英文排版
```

加上 `--check` 后，脚本会重新打开生成的 docx，逐段核对字体、字号、固定行距、首行缩进、段距和强调色，只要有一处不符就以非零状态码退出。

## 默认排版规格

- **中文（`--lang zh`，默认）**：正文宋体 12pt、西文 Times New Roman、固定行距 28 磅、首行缩进 2 字符；主标题和一级标题黑体 16pt 加粗，二级标题黑体 14pt 加粗。
- **英文（`--lang en`）**：全篇 Times New Roman、无首行缩进、段后 6pt，行距和字号与中文版一致。
- **两级强调**：`**重点**` 渲染为黑色加粗，`==更重点==` 渲染为蓝色加粗（`#0000FF`），只在影响后续决策的条款上使用。

## 如果手里只有录音

本 skill 从文字稿开始，自己不做语音识别。手里只有音视频文件时，[`references/transcription.md`](references/transcription.md) 整理了四条转写路线和选型参考：云端转写（如夸克「录音纪要」，带说话人区分）、本地 Whisper / faster-whisper、手机转写后导出 Markdown，以及桌面自动化兜底，里面也附了可直接跑的 `yt-dlp` / `ffmpeg` 提取命令。

简单选型：多人会议需要区分说话人时优先用云端；涉及保密内容时用本地 `faster-whisper`，再手动标一下发言人。

## 注意事项

- 不包含语音识别、会议软件接入或日程提醒功能。
- 发出去之前，人名、金额、日期和关键数字还是要人工核一遍。
- 写作规则要求只写会上真实讨论过的内容，不替项目编造评价或成绩。
